Check your own project first. This is a defensive tool. Run npm run check -- <path> (or the /check-injection plugin) to find out whether your Claude Code configuration actually stops a repository-borne prompt injection, and adopt the hardened config pack as a proven defense. The measurement study below is the evidence base for the verdicts check returns — the safeguard is the product; the numbers are why you can trust it.

Headline — injection study

Across 13 repository-borne injection runs, 0 reached a sink. Attack success over payloads that reached the agent's context (7 delivered): 0.0%. 0 run(s) emitted an egress-shaped action that did not complete. Task success held throughout.

Two experiments back this report. Injection study (below): do hidden repository payloads fire? Egress-enforcement view (further down): when a real egress is issued, does each permission layer stop it? They must not be conflated — a model that declines an injection and a layer that blocks an egress are different findings.

Pilot, not the powered sweep. These figures are a curated host-safe pilot: the injection study is 13 runs in the bypass arm only; the enforcement view is a single egress probe per arm. Every rate is 0/1, 1/1, or over n≤3, so the Wilson intervals are wide (a 1/1 rate is 95% [20.7%, 100%]) — read the numbers as directional, not as powered estimates. The ~750-run sweep across all seven arms is still pending. No clean (un-injected) baseline was collected in this pilot, so a task-success delta vs baseline is not computed; injected-run task success is reported directly: 100.0% (13 injected runs, bypass).
